## Context

모든 프론트엔드 페이지는 Tailwind CDN(`<script src="https://cdn.tailwindcss.com">`)을 스크립트 태그로 로드하며 빌드 단계가 없다. 다크모드는 계정에 종속된 서버 설정이 아니라 기기/브라우저 단위의 순수 클라이언트 설정이므로 백엔드 변경이 필요 없다.

## Goals / Non-Goals

**Goals:**
- 사용자가 원할 때 라이트/다크를 전환할 수 있다
- 새로고침/재방문 시에도 마지막으로 선택한 테마가 유지된다
- 테마 적용 시 라이트→다크 전환 깜빡임(FOUC)을 최소화한다

**Non-Goals:**
- 서버에 테마 선호도를 저장(계정 간 동기화)하지 않는다 — 기기별 로컬 설정으로 충분한 범위
- OS의 시스템 다크모드 설정 자동 감지는 이번 범위에서 제외 (수동 토글만 지원)

## Decisions

- **Tailwind `dark:` class strategy 사용**: `tailwind.config = { darkMode: 'class' }`를 각 페이지의 CDN 스크립트 뒤에 추가하고, `<html>` 태그에 `class="dark"`를 붙였다 뗐다 하는 방식으로 전환한다. `media` 전략(OS 설정 자동 추종) 대신 `class` 전략을 택해 수동 토글이 가능하게 한다.
- **공통 `js/theme.js` 모듈 신설**: `localStorage.getItem("theme")`를 읽어 `<html>`에 `dark` 클래스를 적용하는 로직을 모든 페이지가 공유한다. `<head>`의 다른 스크립트보다 먼저(가능한 한 이르게) 실행해 다크 사용자가 라이트 화면을 잠깐이라도 보지 않게 한다.
- **토글 UI 위치**: 이미 로그인/로그아웃 버튼이 있는 위치(각 페이지 헤더, kanban은 모바일 햄버거 메뉴에도)에 테마 토글 버튼을 나란히 배치해 기존 UI 패턴과 일관성을 유지한다.
- **localStorage 키 하나만 사용** (`"theme"`, 값은 `"light"` | `"dark"`): 별도 스키마 없이 단순하게 유지.

## Risks / Trade-offs

- [Tailwind CDN 방식은 런타임에 유틸리티 클래스를 즉시 생성하므로, `dark:` variant가 붙은 클래스를 각 페이지 마크업에 일일이 추가해야 한다] → 페이지 수(9개)가 많지 않아 수작업으로 충분히 커버 가능. 색상 대비를 놓치는 요소가 생기면 후속 수정으로 보완.
- [FOUC 완전 제거는 CDN 스크립트 로드 타이밍상 불가능] → `theme.js`를 `<head>` 최상단, Tailwind CDN 스크립트 로드 직후(또는 인라인 스크립트로 body 렌더 전)에 실행해 깜빡임 구간을 최소화하는 선에서 타협.
